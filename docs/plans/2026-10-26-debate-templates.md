# 辩论赛辩题模板库（2026-10-26）

状态：已实现（`feat/debate-templates`）。前一版设计随 `9b2eb40`（辩论赛功能）落地，本篇只记录这一次的重构。

## 问题

辩论中心只存一份规则文本和一套（按 Bot 的）说明书。换辩题要手工整段粘贴，队伍成员只能承载一套人设；实践里用户干脆为每个话题重建一支队伍。历届战绩里还写死了第一期的节目名。

## 方案：一套队伍 × 一个模板库

一支辩论队伍（一个「辩论赛直播间」群 + 它的成员），配一个**辩题模板库**。每套模板是一个话题的完整配置：

- `name`：模板名，唯一，≤40 字；用于展示、记忆和战绩里的 `topic`。
- `rules`：规则全文，≤8000 字；首行「辩题：…」会作为开赛时发给主持人的辩题行。
- `personas`：每个成员一张**完整 Bot 卡**（`id, name, role, instructions`）。字段留空 = 开赛时不改动该字段；整卡可以换名字和角色标签。

`state.debate` 升到 `version: 2`：`templates[]` + `activeTemplateId` + `matches[].topic`。旧状态的 `rules` + `personas` 快照在 `ensureDebate` 里迁移成第一套模板（`migrate`），旧战绩保留、无 `topic`。迁移由 debate 模块自管，`store.js` 不动。

## 槽位匹配

模板人设以成员 Bot id 为锚；Bot 被重建（id 变了）时依次按名字、按唯一角色回退（`resolveSlots`），仍解析不到的跳过并出警告。改名单卡冲突（名字被占用）也只降级为警告，不挡整场开赛。

## 端点（`api/bot` 的 `debate` 动作）

- `view`：现字段之外，返回 `templates`（全量）、`activeTemplateId`、live `personas`（新建模板的预填）、带 `topic` 的 `history`；`canStart` 增加「库里要有模板」。
- `save { template }`：新建/更新，校验名字唯一与长度。
- `delete { id }`：删除；删当前场的模板时 `activeTemplateId` 回退到第一套。
- `apply { id }`：把模板卡写入成员（`updateBot`），不开赛。
- `start { templateId }`：套卡 → 归档旧群 → 记忆（带 `topic`）→ 开新群 → 重置消息与主持人开场（附辩题行）。
- `remember` 不变。

## 界面（设置 → 辩论赛）

- 当前这场：场次 + 话题 + 结果；模板下拉 + 两次确认开赛。
- 辩题库：模板行（名称、更新时间、当前徽标）展开编辑：模板名、规则、按成员折叠的完整卡（名字/角色/说明书，留空保持现状）；新建（以当前队伍预填）、复制、保存、保存并应用、两次确认删除。
- 历届战绩：每场显示话题名。

角色标签（控场/正方/反方/评委/核查/气氛）仍驱动流程逻辑（主持人识别、重置文案分支），界面提示它们是赛制的一部分，可改但不要另起炉灶。

## 非目标

多支队伍/多直播间、模板导入导出、模型与思考强度入模板卡——留作后续。
