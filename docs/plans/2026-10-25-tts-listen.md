# 听消息：MiniMax 文字转语音

- 日期：2026-10-25 定稿
- 代码：`ds-bot/src/host/tts.js`（提供方与缓存）、`src/client/cells.js`（Listen 按钮）、`src/client/voice-settings.js`（设置页）、`src/client/text.js`（`speakableText`）

## 为什么

用户要能「听」一条消息：辩论赛的七嘴八舌适合当播客听，普通聊天也有边看边听的场景。要求每个 Bot 一个不同的音色。

DSH 没有给插件暴露语音合成（speech Remote 只有识别），桌面 app 的 Electron 里浏览器 `speechSynthesis` 也没有内置音色，所以合成放在 DS Bot 自己的面上：宿主侧调提供方，客户端播放。提供方选 MiniMax 的 T2A v2：中文系统音色足够多（含播报、青年、御姐、搞笑等角色音色），官方 API、用户自己的密钥，与硬规则「只用原创或可授权材料」相容。浏览器 `speechSynthesis` 仍是语音对话（voice.js）的朗读引擎，两条线互不取代。

## 已定的行为

### 按钮与播放

- 每条 Bot 回复气泡的悬停工具栏（触屏为点按气泡）多一个 Listen 按钮，在 Reply 之后。点击：把气泡文本经 `speakableText` 清洗（去代码块、链接地址和 Markdown 记号，规则从语音对话的 `plainSpeech` 收拢到 `text.js` 共用）后发 `tts` 端点，宿主返回 mp3（base64），浏览器 `<audio>` 播放。
- 一次只播一条：新点击停掉上一条。播放中按钮变为「停止朗读」。失败（未配置、超长、服务拒绝）在工具栏旁显示一行短提示，3 秒后消失。
- 文本上限 10,000 字符（MiniMax 单次上限），超长直接拒绝，不切分。

### 提供方与配置

- 独立模块 `src/host/tts.js`，仿 `web-search.js` 的「独立、可摘」形态，不进 Bot 会话逻辑，不挂任何 Bot 工具。
- 默认 `https://api.minimaxi.com/v1/t2a_v2`、模型 `speech-02-turbo`、音色 `male-qn-qingse`；服务地址、Group ID、模型（02/2.6/2.8 的 turbo 与 hd）、全局默认音色、语速（0.5–2）都在设置 → 语音页配，存 `state.tts`。
- **密钥不走 state.json**：MiniMax API key 存密钥库（名字固定 `MINIMAX_TTS_KEY`，设置 → 语音页写入，设置 → 密钥页可见可删），宿主合成时读取，值不出宿主、不回传客户端。
- 每个 Bot 可单独选音色：设置页列出全部 Bot，各配一个（系统音色精选列表 + 自定义 voice ID），没配的用默认音色。按发言 Bot 选音色，辩手、主持人、评委天然区分。

### 缓存与端点

- 合成结果按 `sha256(文本+音色+语速+模型+地址)` 存 `数据目录/tts-audio/<hash>.mp3`，内存加磁盘两级；重听同一句零成本。超过 300 个文件时按修改时间删最旧。
- `api/bot` 新端点：`tts`（合成一条）与 `tts-save`（写 `state.tts`）。两者都不在只读白名单 `READS` 里：花钱的操作必须由持有团队的主宿主执行。

## 不做什么

- 自动连播和播放队列不在本期；群聊「广播模式」见[群聊朗读：自动连播与播放控制](2026-10-25-tts-broadcast.md)。
- 不做按句切分与流式合成；首版整段一次请求。
- 不做设置页里的音色试听（用 MiniMax 平台的试听页）。
- 不改 DSH、不打包任何第三方语音资产。

## 已知限制

- 超过 10,000 字符的消息拒绝朗读（不截断、不切分）。
- 只读宿主（另一个 dsh 持有团队）上按钮会收到拒绝提示。
- MiniMax 的限速与配额错误原样透出，不自动重试。
- 缓存无 TTL，音色或语速变了自然换 key，旧文件等容量淘汰。
