# 群聊朗读：自动连播与播放控制

- 日期：2026-10-25 定稿
- 代码：`ds-bot/src/client/listen-core.js`（播放队列与手动朗读）、`src/client/listen.js`（React 与宿主端点接线）、`src/client/cells.js`（群消息入队、Listen 按钮）、`src/client/header.js`（群头部开关与播放条）、`src/client/text.js`（`speakableSpeech`）
- 前置：[听消息：MiniMax 文字转语音](2026-10-25-tts-listen.md)

## 为什么

上一期只做了逐条 Listen。辩论赛要在群里连续听：主持人、辩手、核查官、评委依次发言，每条用发言 Bot 自己的音色，听起来像一档节目。群消息本身带 `botId`，音色可以按发言者直接选；缺的是「新消息自动排队、连续播放、能跳过和回退」。

## 已定的行为

### 开关与范围

- 群聊头部（房间名旁边）多一个喇叭按钮。点击开启「朗读新消息」：从现在起到达这个群的新 Bot 消息自动入队朗读。再点一次，或在播放条上点停止，即关闭。
- 只对群聊生效。普通 Bot 私聊仍用逐条 Listen。
- 群里所有 Bot 的消息都读，不按角色筛选。用户自己的消息、系统事件行、失败提示、群成员状态不读。
- 开启时不补读历史：只有时间晚于开启时刻的消息入队。翻旧消息、重新渲染不会重播（按消息 key 去重）。
- 离开这个群（切换会话）就停止并清空队列。不留下看不见的后台播放。

### 播放

- 一次只播一条，按到达顺序排队。当前一条开始播放时，后台预取队列里的下一条，缩短停顿。
- 每条按发言 Bot 的音色：沿用 `state.tts.voices[botId]`，没配的用默认音色；模型、语速、服务地址沿用语音设置。
- 群头部下方出现一条播放条：当前朗读的 Bot 名、待读条数、上一条、下一条、停止。合成中显示准备状态；出错时在播放条上显示一行短提示，4 秒后消失。
- 上一条：当前条刚播不久则从头重播；否则回到上一条（当前条放回队首，播完上一条后继续）。下一条：跳过当前条，播下一条；没有下一条就停下等待。停止：关闭朗读、清空队列。
- 手动 Listen 与自动连播互斥：点某条消息的 Listen 会关闭该群的自动连播并单独播这一条；开启自动连播会停掉正在播放的手动朗读。

### 文本

- 朗读前经过 `speakableSpeech`：先按 `speakableText` 去掉消息头、代码块、链接地址和 Markdown 记号；再丢掉辩论发言开头的阶段标签 `【正方立论-正方】`（只丢掉形如 `【…-…】` 的首个标签，避免误伤普通 `【重点】`），以及 `【申请核查：…】` 这类流程标记。
- 单条超过 10,000 字符（MiniMax 单次上限）不入队、不切分，播放条提示一次后跳过。
- 清洗后为空的消息（只有标签、代码或链接）跳过。

### 队列与失败

- 待读队列最多 30 条；满了以后新消息跳过并提示一次，已有队列继续播。
- 合成失败：跳过这一条继续下一条，播放条显示原因；连续 3 条失败（多半是密钥、只读宿主或服务不可用）就停止朗读，避免持续计费。
- 音频播放被浏览器拒绝（自动播放策略、音频损坏）：立即停止朗读并提示。
- 关闭朗读、切换会话或停止时，终止尚未返回的合成请求结果，避免它在关闭后又响起来。

## 技术

- 新模块 `src/client/listen-core.js`，导出可测试的 `createListening({ synthesize, play })` 工厂；`src/client/listen.js` 用宿主 `tts` 端点、浏览器 `Audio` 和 React hooks 把它接到界面：
  - 状态：`roomId`、开启时刻、当前条、待读队列、最近播放历史、通知文案。订阅者用 `useState` + `useEffect` 订阅，避免新增 React 版本依赖。
  - `enqueue` 负责房间与时间过滤、key 去重、清洗后文本的上限检查、队列上限。
  - `previous` / `next` / `disable` 用代次号让过期的异步合成结果失效。
  - 合成结果按消息 key 缓存在内存（data URL），上一条/重播不再请求宿主；宿主磁盘缓存继续负责跨重启。
  - 手动朗读也走这个模块的同一个播放器，保证与队列不会同时出声。
- `cells.js`：
  - `GroupMessage` 把 `roomId`、每条文本的时间、消息 key 传给 `Bubbles`；`Bubble` 在非流式且消息已落定时调用 `useAutoSpeech` 入队。
  - `stackReplies` 保留每条回复自己的时间，连续同 Bot 的多段话仍是一条一条读。
  - 群历史里的 `post_to_group` 转贴同样有 `roomId` 与时间，因此也会被朗读；转贴的作者是主持人，音色也按主持人（本期不做按阶段标签映射音色）。
  - 逐条 Listen 改为调用 `speakManual`，不再自己维护 `<audio>`。
- `header.js`：房间头部的开关与播放条；未开启文字转语音或未保存密钥时点击只提示去 设置 → 语音 配置，不发起请求。
- 样式在 `src/client/styles.js`；文案在 `src/client/i18n.js`，界面文字仍为英文。

## 不做什么

- 不做跨群/后台播放，不做迷你播放器常驻。离开群即停。
- 不做按成员或角色筛选、不做阶段标签到音色的映射、不做弹幕单独音色。
- 不做按句切分与流式合成；仍按整条消息一次合成。
- 不改宿主侧 `tts` 端点与缓存，不改 DSH，不打包第三方语音资产。

## 已知限制

- 自动连播只在群聊窗口打开时工作；切走就停。
- 合成在整条消息完成后才开始播放，长消息的首响会慢一些。
- 只读宿主会拒绝 `tts`；连续失败后自动停止，并在播放条提示原因。
- 计时以浏览器时钟为准；宿主与浏览器时钟偏差很大时，开启瞬间可能漏读或重读一条。
